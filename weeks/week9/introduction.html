Woche 9: Einführung in KI-Agenten, Tool Calling & Agenten-Skills

Die Evolution künstlicher Intelligenz vollzieht sich in einem rasanten Übergang von passiven Sprachmodellen, die Texte vorhersagen, hin zu autonomen KI-Agenten, die in geschlossenen Regelkreisen agieren. Ein Agent ist nicht mehr nur ein statistisches Orakel, sondern ein aktiver Akteur: Er nimmt seine Umwelt wahr (Perception), plant und reflektiert sein Vorgehen (Reasoning) und führt gezielte Aktionen aus (Action), um komplexe, offene Probleme zu lösen.

In dieser Woche brechen wir das Paradigma der reinen Textgenerierung auf. Wir untersuchen das ReAct-Pattern (Reasoning and Acting) und das technische Fundament von Tool Calling (Function Calling), über das Modelle Programmierfunktionen autonom ausführen können. Zudem werfen wir einen Blick auf das Ökosystem der Google Gemma-Skills zur modularen Agentenerweiterung und bereiten uns auf Problem Set 9 vor, in dem Ihr Agent als autonomer Ingenieur eine JAX-beschleunigte Mandelbrot-Simulation optimiert.

🔄 Vom Sprachmodell zum autonomen Akteur

Klassische Large Language Models (LLMs) arbeiten autoregressiv: Sie erhalten einen Prompt und sagen das statistisch wahrscheinlichste nächste Token voraus. Obwohl dies für kreatives Schreiben oder Code-Erstellung faszinierend gut funktioniert, stoßen reine LLMs bei dynamischen, unvorhersehbaren Problemen an eine harte Wand. Sie besitzen kein kontinuierliches Feedback aus der realen Welt und neigen bei komplexen Berechnungen oder zeitkritischen Fakten zu Halluzinationen.

Die Transformation zum KI-Agenten löst diese Limitierung auf, indem das Modell in eine zyklische Feedbackschleife mit seiner Umgebung eingebettet wird. Ein Agent basiert auf drei Säulen:

👁️ Wahrnehmung (Perception)

Der Agent nimmt Informationen aus seiner Umwelt auf. Dies können Text-Prompts, Benutzer-Eingaben, API-Rückmeldungen, Logdateien oder Bilddaten (Multimodalität) sein. Diese Inputs aktualisieren den Kontext des Modells.

🧠 Denken (Reasoning)

Vor einer Aktion analysiert den Zustand. Es zerlegt Aufgaben in Teilziele, plant Strategien (Chain of Thought), evaluiert Zwischenergebnisse und entscheidet, ob weitere Daten oder externe Berechnungen nötig sind.

🛠️ Handeln (Action)

Der Agent interagiert mit der Außenwelt. Über definierte Schnittstellen (Tools) führt er Code aus, liest/schreibt Dateien, fragt Datenbanken ab, sendet Netzwerkanfragen oder ruft physikalische Systemsimulationen auf.

📖 Das ReAct-Pattern (Reasoning and Acting)

Wie koordiniert ein Agent das Zusammenspiel aus Denken und Handeln? Der bahnbrechende Ansatz hierfür ist das ReAct-Pattern (Yao et al., 2022). Vor ReAct wurden zwei Strategien getrennt voneinander genutzt:

  • Reason-Only (z. B. Chain of Thought - CoT): Das Modell generiert Zwischenschritte der Argumentation im Text, ist aber isoliert von externen Werkzeugen. Es kann nicht auf aktuelle Daten zugreifen oder Rechenfehler korrigieren.
  • Act-Only (z. B. WebGPT): Das Modell ruft sofort Werkzeuge auf und erhält Antworten. Ohne logische Planungsschritte verliert es jedoch schnell den Fokus auf das globale Ziel, verstrickt sich in Schleifen oder scheitert an komplexen Logikpfaden.

ReAct verwebt Denken und Handeln dynamisch. Das Modell schreibt abwechselnd einen gedanklichen Planungsschritt (Thought), entscheidet sich für eine Aktion (Action), wartet auf das reale Ergebnis aus der Umwelt (Observation) und wiederholt diesen Zyklus:

⚙️ TYPISCHER REACT-ABLAUF (TRACE) Loop #1
[Thought] Ich muss die maximale Komplexität im Mandelbrot-Grenzbereich bei c = -0.7436438870371587 + 0.13182590420531197i untersuchen. Zuerst führe ich die Simulation mit einem moderaten Zoomfaktor von 1000 aus, um die grobe Pixeldichte zu erfassen.
[Action] run_mandelbrot_simulation(center_real=-0.7436438870371587, center_imag=0.13182590420531197, zoom=1000.0, max_iterations=500)
[Observation] { "entropy": 2.15, "boundary_complexity": 0.45, "pixel_density": 0.38, "status": "SUCCESS" }
Loop #2
[Thought] Die Entropie (2.15) deutet auf eine mäßige Strukturierung hin. Ich erhöhe den Zoomfaktor auf 15000 und die Iterationstiefe auf 1000, um feinere Verzweigungen im Seahorse Valley sichtbar zu machen.
[Action] run_mandelbrot_simulation(center_real=-0.7436438870371587, center_imag=0.13182590420531197, zoom=15000.0, max_iterations=1000)
[Observation] { "entropy": 4.89, "boundary_complexity": 0.92, "pixel_density": 0.76, "status": "SUCCESS" }
[Thought] Die Entropie ist sprunghaft auf 4.89 gestiegen, was eine extrem hohe Detaildichte und komplexe fraktale Filamente beweist. Die Zielkoordinaten für das Seahorse Valley sind damit optimal erfasst. Ich schließe die Suche ab.

🛠️ Wie Tool Calling unter der Haube funktioniert

Damit ein LLM ein Werkzeug aufrufen kann, muss es wissen, welche Werkzeuge existieren und wie sie angesprochen werden. Dieser Prozess läuft über standardisierte Tool Calling API-Protokolle ab, die in modernen Frameworks (wie der Gemini API) nativ integriert sind:

1. Die Deklaration (JSON Schema)

Der Entwickler übergibt dem Modell zusammen mit dem Prompt eine Liste von verfügbaren Funktionen. Jede Funktion wird durch eine präzise Beschreibung und ein JSON Schema definiert, welches die Parameternamen, Datentypen und Pflichtfelder spezifiziert.

2. Der Modell-Entschluss (Function Call Output)

Das Modell generiert keine menschliche Antwort, sondern erkennt anhand des Kontexts, dass es ein Tool benötigt. Es stoppt die reguläre Textgenerierung und gibt ein strukturiertes JSON-Objekt aus, das den Funktionsnamen und die berechneten Argumente enthält.

3. Die lokale Ausführung & Feedback

Die Anwendungsplattform (die Software, die das LLM steuert) fängt diese strukturierte Ausgabe ab, parst sie, führt die entsprechende Funktion auf der lokalen Maschine aus und sendet das Ergebnis als Tool Response zurück an das Modell. Das LLM verarbeitet dieses Ergebnis im nächsten Schritt.

Beispiel einer Tool-Deklaration (JSON Schema)

Ein Schema beschreibt die Schnittstelle so detailliert, dass das Modell semantisch versteht, welche Parameter es übergeben muss:

📦 Das Ökosystem der Agenten-Skills (Google Gemma-Skills)

In hochprofessionellen Agentensystemen werden Tools und Systemprompts nicht ad-hoc im Code verstreut. Stattdessen werden sie in modulare, wiederverwendbare Kapseln verpackt, die sogenannten Agenten-Skills.

Die führenden Standard-Spezifikationen hierfür sind in den Repositories google/skills und google-gemma/gemma-skills definiert. Ein Gemma-Skill ist eine in sich geschlossene Verzeichnisstruktur, die dem Agenten eine spezifische neue Fähigkeit verleiht:

📁 Struktur: my-simulation-skill/
├── 📄 SKILL.md (Metadaten & Prompt-Befehle)
├── 📁 tools/ (JSON Schema Deklarationen)
├── 📁 scripts/ (Python-Code & JAX Simulationsskripte)
├── 📁 examples/ (Few-Shot Interaktionsbeispiele)
└── 📁 references/ (Handbücher & API-Dokumente)

Funktionsweise und Skill-Registrierung:

1. Deklarative Steuerung (SKILL.md): Die Hauptdatei eines Skills enthält ein YAML-Frontmatter (mit `name` und `description`). Diese Metadaten erlauben es dem Orchestrator, Skills bei passenden Anfragen dynamisch zu triggern und die Kognitionsanweisungen direkt in den Systemprompt des LLMs einzubetten.

2. Modularer Funktionsumfang: Alle in `tools/` deklarierten Schemas werden automatisch geladen und als API-Werkzeuge für das Modell registriert. Das Modell kann somit durch einfache Prompt-Befehle hochkomplexe, in `scripts/` hinterlegte physikalische JAX-Modelle steuern, ohne den zugrundeliegenden Applikationscode modifizieren zu müssen.

🔬 Vorbereitung Problem Set 9: Der Agent als Ingenieur

Im bevorstehenden Problem Set 9 heben wir die Systemsimulation auf ein neues Niveau. Sie werden eine mathematische Simulation nicht mehr manuell steuern, sondern Ihren Agenten in die Pflicht nehmen. Die Aufgabe besteht darin, eine JAX-beschleunigte Mandelbrot-Simulation als Tool zu deklarieren und das Modell anzuweisen, eine komplexe Zielkoordinate autonom zu finden.

◆ Die Mandelbrot-Gleichung und JAX-Beschleunigung

Die Mandelbrot-Menge ist definiert über die Iteration der komplexen quadratischen Gleichung:

$$ z_{n+1} = z_n^2 + c $$

Wobei $z_0 = 0$ gilt und $c$ die Koordinate in der komplexen Ebene darstellt. Ein Punkt gehört zur Mandelbrot-Menge, wenn die Folge unter Iteration beschränkt bleibt ($|z_n| \le 2$). Für die grafische Darstellung berechnen wir die Anzahl der Iterationsschritte $n$ bis zum Entweichen ($|z_n| > 2$).

Da dies für ein Gitter aus $1000 \times 1000$ Pixeln millionenfach berechnet werden muss, implementieren wir die Iterationsschleife in JAX. Dank `@jax.jit` und Vektorisierung läuft diese High-Performance-Berechnung in wenigen Millisekunden ab: 

import jax
import jax.numpy as jnp

@jax.jit
def mandelbrot_kernel(c, max_iters):
    # Führt die Iteration auf einem Vektor von komplexen Zahlen c aus
    def body_fn(val):
        z, count, active = val
        next_z = z**2 + c
        next_active = active & (jnp.abs(next_z) <= 2.0)
        next_count = jnp.where(next_active, count + 1, count)
        return next_z, next_count, next_active

    def cond_fn(val):
        _, count, active = val
        return jnp.any(active) & (jnp.min(count) < max_iters)

    z = jnp.zeros_like(c)
    count = jnp.zeros_like(c, dtype=jnp.int32)
    active = jnp.ones_like(c, dtype=jnp.bool_)

    _, final_counts, _ = jax.lax.while_loop(cond_fn, body_fn, (z, count, active))
    return final_counts

◆ Der kognitive Regelkreis in Aktion

Ihr Agent erhält die Zielvorgabe, Koordinaten von hoher struktureller Komplexität (z. B. das berühmte „Seahorse Valley“) zu ermitteln. Dazu wird das obige JAX-Skript als Tool registriert. Der Agent führt eine Simulation aus, analysiert die zurückgegebenen Metriken (wie die Entropie der Fluchtzeiten oder die Pixeldichte am Rand der Menge) und verschiebt selbstständig das Zoom-Fenster, bis er das Optimierungsziel erreicht hat.
