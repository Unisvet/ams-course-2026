Week 9: Introduction to AI Agents, Tool Calling & Agent Skills

The evolution of artificial intelligence is taking place in a rapid transition from passive language models that predict text to autonomous AI agents acting in closed-loop systems. An agent is no longer just a statistical oracle, but an active player: it perceives its environment (Perception), plans and reflects on its actions (Reasoning), and executes targeted actions (Action) to solve complex, open-ended problems.

This week, we break the paradigm of pure text generation. We examine the ReAct pattern (Reasoning and Acting) and the technical foundation of Tool Calling (Function Calling), through which models can autonomously execute programming functions. We also take a look at the ecosystem of Google Gemma Skills for modular agent extension and prepare for Problem Set 9, where your agent will optimize a JAX-accelerated Mandelbrot simulation as an autonomous engineer.

🔄 From Language Model to Autonomous Actor

Classic Large Language Models (LLMs) work autoregressively: they receive a prompt and predict the statistically most likely next token. Although this works fascinatingly well for creative writing or code generation, pure LLMs hit a hard wall when faced with dynamic, unpredictable problems. They have no continuous feedback from the real world and tend to hallucinate when dealing with complex calculations or time-critical facts.

The transformation into an AI agent resolves this limitation by embedding the model into a cyclic feedback loop with its environment. An agent is based on three pillars:

👁️ Perception

The agent receives information from its environment. This can include text prompts, user inputs, API feedback, log files, or image data (multimodality). These inputs update the model's context.

🧠 Reasoning

Before taking an action, the agent analyzes the state. It breaks down tasks into sub-goals, plans strategies (Chain of Thought), evaluates intermediate results, and decides whether further data or external calculations are needed.

🛠️ Action

The agent interacts with the outside world. Through defined interfaces (tools), it executes code, reads/writes files, queries databases, sends network requests, or calls physical system simulations.

📖 Theoretical Introduction

How does an agent coordinate the interplay of thinking and acting? The groundbreaking approach for this is the ReAct pattern (Yao et al., 2022). Before ReAct, two strategies were used separately:

  • Reason-Only (e.g., Chain of Thought - CoT): The model generates intermediate steps of reasoning in text but is isolated from external tools. It cannot access real-time data or correct calculation errors.
  • Act-Only (e.g., WebGPT): The model immediately calls tools and receives answers. However, without logical planning steps, it quickly loses focus on the global goal, gets caught in loops, or fails at complex logic paths.

ReAct dynamically weaves reasoning and acting together. The model alternately writes a mental planning step (Thought), decides on an action (Action), waits for the real result from the environment (Observation), and repeats this cycle:

⚙️ TYPICAL REACT FLOW (TRACE) Loop #1
[Thought] I need to examine the maximum complexity in the Mandelbrot boundary at c = -0.7436438870371587 + 0.13182590420531197i. First, I'll run the simulation with a moderate zoom factor of 1000 to capture the rough pixel density.
[Action] run_mandelbrot_simulation(center_real=-0.7436438870371587, center_imag=0.13182590420531197, zoom=1000.0, max_iterations=500)
[Observation] { "entropy": 2.15, "boundary_complexity": 0.45, "pixel_density": 0.38, "status": "SUCCESS" }
Loop #2
[Thought] The entropy (2.15) suggests moderate structuring. I'll increase the zoom factor to 15000 and the iteration depth to 1000 to reveal finer branching in the Seahorse Valley.
[Action] run_mandelbrot_simulation(center_real=-0.7436438870371587, center_imag=0.13182590420531197, zoom=15000.0, max_iterations=1000)
[Observation] { "entropy": 4.89, "boundary_complexity": 0.92, "pixel_density": 0.76, "status": "SUCCESS" }
[Thought] The entropy jumped to 4.89, proving extremely high detail density and complex fractal filaments. The target coordinates for the Seahorse Valley are thus optimally captured. I'll conclude the search.

🛠️ How Tool Calling Works Under the Hood

For an LLM to call a tool, it must know which tools exist and how to address them. This process takes place via standardized Tool Calling API protocols that are natively integrated into modern frameworks (such as the Gemini API):

1. The Declaration (JSON Schema)

The developer provides the model with a list of available functions along with the prompt. Each function is defined by a precise description and a JSON Schema specifying parameter names, data types, and required fields.

2. The Model's Decision (Function Call Output)

The model does not generate a human-like response, but recognizes from the context that it needs a tool. It stops regular text generation and outputs a structured JSON object containing the function name and calculated arguments.

3. Local Execution & Feedback

The application platform (the software controlling the LLM) intercepts this structured output, parses it, executes the corresponding function on the local machine, and sends the result back to the model as a Tool Response. The LLM processes this result in the next step.

Example of a Tool Declaration (JSON Schema)

A schema describes the interface in such detail that the model semantically understands which parameters it needs to pass: 

{
  "name": "run_mandelbrot_simulation",
  "description": "Executes a JAX-accelerated Mandelbrot iteration on a complex coordinate window.",
  "parameters": {
    "type": "OBJECT",
    "properties": {
      "center_real": {
        "type": "NUMBER",
        "description": "Real part of the center in the complex coordinate system."
      },
      "center_imag": {
        "type": "NUMBER",
        "description": "Imaginary part of the center in the complex coordinate system."
      },
      "zoom": {
        "type": "NUMBER",
        "description": "Zoom factor (larger values mean a closer view)."
      },
      "max_iterations": {
        "type": "INTEGER",
        "description": "Maximum iteration depth per pixel (determines details)."
      }
    },
    "required": ["center_real", "center_imag", "zoom"]
  }
}

📦 The Agent Skills Ecosystem (Google Gemma Skills)

In high-professional agent systems, tools and system prompts are not scattered ad-hoc in the code. Instead, they are packaged into modular, reusable capsules called agent skills.

The leading standard specifications for this are defined in the repositories google/skills and google-gemma/gemma-skills. A Gemma skill is a self-contained directory structure that gives the agent a specific new capability:

📁 Structure: my-simulation-skill/
├── 📄 SKILL.md (Metadata & prompt instructions)
├── 📁 tools/ (JSON Schema declarations)
├── 📁 scripts/ (Python code & JAX simulation scripts)
├── 📁 examples/ (Few-shot interaction examples)
└── 📁 references/ (Handbooks & API docs)

Functionality and Skill Registration:

1. Declarative Control (SKILL.md): The main file of a skill contains a YAML frontmatter (with `name` and `description`). This metadata allows the orchestrator to dynamically trigger skills upon matching requests and embed cognitive instructions directly into the LLM's system prompt.

2. Modular Feature Set: All schemas declared in `tools/` are automatically loaded and registered as API tools for the model. The model can thus control highly complex physical JAX models stored in `scripts/` through simple prompt commands without needing to modify the underlying application code.

◆ The Mandelbrot Equation and JAX Acceleration

The Mandelbrot set is defined by the iteration of the complex quadratic equation:

$$ z_{n+1} = z_n^2 + c $$

Where $z_0 = 0$ and $c$ represents the coordinate in the complex plane. A point belongs to the Mandelbrot set if the sequence remains bounded under iteration ($|z_n| \le 2$). For graphical representation, we calculate the number of iteration steps $n$ until escape ($|z_n| > 2$).

Since this must be calculated millions of times for a grid of $1000 \times 1000$ pixels, we implement the iteration loop in JAX. Thanks to `@jax.jit` and vectorization, this high-performance calculation runs in just a few milliseconds: 

import jax
import jax.numpy as jnp

@jax.jit
def mandelbrot_kernel(c, max_iters):
    # Executes iteration on a vector of complex numbers c
    def body_fn(val):
        z, count, active = val
        next_z = z**2 + c
        next_active = active & (jnp.abs(next_z) <= 2.0)
        next_count = jnp.where(next_active, count + 1, count)
        return next_z, next_count, next_active

    def cond_fn(val):
        _, count, active = val
        return jnp.any(active) & (jnp.min(count) < max_iters)

    z = jnp.zeros_like(c)
    count = jnp.zeros_like(c, dtype=jnp.int32)
    active = jnp.ones_like(c, dtype=jnp.bool_)

    _, final_counts, _ = jax.lax.while_loop(cond_fn, body_fn, (z, count, active))
    return final_counts

◆ The Cognitive Control Loop in Action

Your agent will be given the objective to determine coordinates of high structural complexity (e.g., the famous "Seahorse Valley"). To do this, the JAX script above will be registered as a tool. The agent runs a simulation, analyzes the returned metrics (such as the entropy of escape times or the pixel density at the set's edge), and independently moves the zoom window until it has reached the optimization goal.
