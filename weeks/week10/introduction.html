Woche 10: Einführung in das Agent Development Kit (ADK)

Bisher haben wir in unseren Python-Skripten Foundation Models primär als aufrufbare Funktionen genutzt. Wir haben manuell Chat-Historien gepflegt, JSON-Antworten geparst und komplexe „Thought-Action-Observation“-Schleifen (ReAct) programmiert, damit das Modell Werkzeuge nutzen kann. Jeder Ablauf war starr und musste im Detail von uns diktiert werden.

Mit dem Agentic Engineering ändert sich dieses Paradigma grundlegend: Wir wechseln vom Diktat zur Delegation. Der Entwickler nutzt eine moderne Umgebung (z. B. die Antigravity IDE) und beschreibt dem KI-Agenten das Ziel in natürlicher Sprache („Vibe Coding“). Der Agent plan autonom, schreibt Code, orchestriert Subagenten, testet Ergebnisse in einer sicheren Sandbox und korrigiert Fehler eigenständig. Das Google Agent Development Kit (ADK) liefert uns das Code-Framework, um genau solche autonomen, zustandsbehafteten Agenten in Python zu bauen.

🎯 Lernziele der Woche

  • 1. Delegation statt Diktat: Verstehen des Paradigmenwechsels vom manuellen Code-Debugging hin zu autonomen, zielgesteuerten Agenten-Systemen.
  • 2. ADK-Architektur beherrschen: Anatomie eines Agenten anhand der vier Säulen (Model, Name, Description, Instruction) verstehen und anwenden.
  • 3. Memory & State-Tracking: Funktionsweise von implizitem Zustands-Management und der autonomen Fehlerkorrektur im Perceive-Think-Act Loop.
  • 4. Visual Debugging & Web UI: Starten lokaler Server via uv und visuelle Analyse der Chain of Thought im Browser-Interface.

📦 1. Installation und Setup mit uv

Das ADK klinkt sich nahtlos in moderne Python-Workflows ein. Da wir in unserem Kurs auf High-Performance und reproduzierbare Umgebungen setzen, nutzen wir uv anstelle des veralteten pip. Wir fügen das ADK direkt unserem Projekt hinzu: 

uv add google-adk

Sensible Schlüssel lagern wir sicher in eine .env-Datei aus, die das ADK beim Start automatisch ausliest: 

GOOGLE_API_KEY="dein_api_key_hier"

Mit dem integrierten Kommandozeilen-Befehl generieren wir anschließend sofort ein lauffähiges Agenten-Projekt mit der korrekten Struktur (__init__.py und agent.py): 

uv run adk create my_first_agent

🧬 2. Anatomie eines Agenten (agent.py)

Ein Agent wird im ADK über vier zentrale Kernparameter definiert:

🤖 1. model

Das kognitive LLM-Gehirn. Wir nutzen gemini-3.5-flash für extreme Latenzvorteile und logische Stärke.

🏷️ 2. name

Der eindeutige Systemname (z. B. observer_prime) für das interne Routing im ADK-System.

📝 3. description

Fähigkeiten-Beschreibung. Unabdingbar in Multi-Agenten-Systemen (MAS) für autonomes Task-Routing.

📜 4. instruction

Der System-Prompt. Definiert Persönlichkeit, Handlungsspielraum, Regeln und Detailwissen.

Implementierungsbeispiel in Python:
from google.adk.agents.llm_agent import Agent

root_agent = Agent(
    model='gemini-3.5-flash',
    name='reactor_overseer',
    description='Ein spezialisierter Agent für Systemsimulationen.',
    instruction='Du bist ein präziser Ingenieur. Überwache Parameter und nutze Tools zur Stabilisierung.'
)

🔄 3. State-Tracking & Memory-Management

Klassische API-Aufrufe sind zustandslos (stateless) – das Modell vergisst nach jeder Antwort alles. Das ADK löst dieses Problem durch ein implizites Memory-Management. Das System speichert den State (Zustand) der Konversation und die Ergebnisse von Funktionsaufrufen automatisch. Der integrierte Perceive ➔ Think ➔ Act ➔ Check Loop sorgt dafür, dass der Agent Fehler bei Werkzeugaufrufen erkennt, die Fehlermeldung aus seinem Gedächtnis liest und selbstständig neue Parameter ausprobiert, ohne dass Ihr Programm abstürzt oder Sie manuell eingreifen müssen.

🖥️ 4. Ausführung und Testen (CLI vs. Web)

Das ADK bietet standardmäßig fertige Schnittstellen, um sofort mit Agenten zu interagieren, ohne ein eigenes Frontend bauen zu müssen:

📟 Interaktive CLI-Shell

Mit dem Befehl uv run adk run cognitive_core starten Sie den Agenten in einer textbasierten interaktiven Konsole. Perfekt für schnelle, schlanke Tests direkt aus dem Terminal.

🌐 Lokale Web-UI

Der Befehl uv run adk web startet einen lokalen Server (standardmäßig auf http://localhost:8000). Im Browser-Chat sehen Sie live, wie der Agent denkt (Chain of Thought) und welche Tools er aufruft – das ideale Tool für visuelles Debugging!

📖 Literatur & Ressourcen

Für ein tieferes wissenschaftliches und praktisches Verständnis des Agent Development Kits (ADK) und moderner agentischer Entwicklung werden die folgenden Veröffentlichungen und offiziellen Ressourcen dringend empfohlen:

  • Google Agent Development Kit (ADK) Dokumentation Die offizielle Entwicklerdokumentation und der Integrationsleitfaden zum Erstellen, Orchestrieren und Evaluieren von Multi-Agenten-Systemen mit Googles ADK. adk.dev
  • Agent Garden (google/adk-samples) Das offizielle Google-Repository mit Beispiel-Agenten, Entwurfsmustern und Boilerplate-Code zur Demonstration der ADK-Nutzung. github.com/google/adk-samples
  • Google ADK Python Core Repository Das Open-Source-Repository der Python-ADK-Implementierung mit Kernklassen (`Agent`, `Workflow`), Ausführungs-Engines und Web-UI-Runner. github.com/google/adk
  • Der Aufstieg von „Vibe Coding“ & Agentischen Workflows (Karpathy, Feb. 2025) – Untersucht den Paradigmenwechsel von der manuellen Syntaxbearbeitung hin zur Delegation an autonome Agenten-Schleifen. Andrej Karpathys Vibe-Coding-Essay auf X
  • Anthropic Research: Building Effective Agents (Anthropic, 2024) – Ausführlicher Leitfaden zu agentischen Entwurfsmustern, Unterscheidung zwischen deterministischen Workflows und dynamischen Agenten sowie Orchestrator-Worker-Architekturen. anthropic.com/research/building-effective-agents
  • ReAct: Synergizing Reasoning and Acting in Language Models (Yao et al., 2022) – Das fundamentale Research-Paper zur Verknüpfung von Chain-of-Thought-Reasoning mit aktiver Werkzeugausführung in ADK-Agenten. arXiv:2210.03629
  • Model Context Protocol (MCP) Spezifikation Das offene Standardprotokoll zur sicheren Anbindung externer Datenquellen, Dateien und Tools an LLM-Agenten. modelcontextprotocol.io
